# Optional Tengo module

This development module embeds Tengo v2.17.0 over the existing source/query,
extraction and in-memory edit APIs. Core parsing and the default CLI do not depend
on Tengo. It requires a checked-out feature revision; its local root-module
replacement is intentional while these APIs remain unreleased.

Build one self-contained, CGO-free executable from the repository root:

```sh
CGO_ENABLED=0 go -C script build -o ../gtroff ./cli
./gtroff script script/examples/inspect.tengo script/examples/environment.1
```

No external interpreter, shell, Python, Node or terminal package is required for
regular execution. The optional entrypoint injects the engine-free
`scriptapi.Backend` into the shared CLI environment and uses its documented
flags-before-input dispatch. The core's annotated commands, inventory, man pages
and completion remain generated by pinned gosubc; default builds explain how to
enable the missing backend. The optional binary also supports ordinary core
commands. See [the script guide](../docs/script.md) for APIs, capabilities and
resource/serialization contracts.

A read-only extraction program:

```tengo
selected := doc.query("section[name=ENVIRONMENT] definition")
each := func(values, fn) { for value in values { fn(value) } }
each(selected, func(match) {
    if match.term == "TOOL_HOME" {
        doc.emit_json({term: match.term, description: match.text,
                       file: match.source, line: match.line})
    }
})
```

Use `doc.extract(selector, "jsonl")` for the existing structured extraction
records, including separate term/description and original-source provenance.
No environment-variable business schema is built into the generic library.

`Run` takes explicit captured sources and returns staged output, a private working
document and optional write intents after success. It never acquires I/O
capabilities. Editing and write-request creation default off. CLI filesystem
writing separately requires an explicitly authorized destination or in-place
flag; it reuses all-original-source hash/alias/staging/rollback guards. A failed
program publishes none of its partial edits, emissions or requests.

`NewSession` and `script --repl` retain native globals/closures and the working
document across transactional cells. Failed cells roll back their candidate
state; failed output remains pending for explicit retry/discard. `--in-place`
authorizes `:commit` in interactive mode, preserving guards across cells and
advancing them only after successful commits. [Session API and controls](../docs/script-repl.md).

```sh
./gtroff script --repl script/examples/environment.1
./gtroff script --repl --prompt=false script/examples/environment.1 < script/examples/session.tengo
```

Verification:

```sh
go -C script test -count=1 ./...
go -C script test -race -count=1 ./...
go -C script vet ./...
go -C script test . -run '^TestScriptScenarios$' -update-script
go -C script test . -run '^TestREPLScenarios$' -update-repl
go -C script test . -run '^$' -fuzz '^FuzzNativeExactSource$' -fuzztime 15s
```

TXTAR expectations are generated only with the explicit update flag, from actual
native programs and source snapshots. Inspect changes and rerun ordinary tests.
Go examples are executable in `example_test.go`; `cli/main_test.go` builds/runs the
actual optional binary. CI verifies both the independent core and this module,
including Go/js wasm execution when the verification host supplies Node.

The native AST adapter inserts private statement/block checkpoints to bound
non-allocating loops and to check deadlines cooperatively on Go/js. This preserves
native Tengo parsing and original script locations; it is not an alternative
language or VM. Steps are checkpoints, not exact VM instructions. Object counts
are not heap-byte quotas, and process-global Tengo value limits are not mutated.
Same-process scripts and host callbacks are not an OS security sandbox. See the
guide before using untrusted programs.
